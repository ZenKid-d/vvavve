# vvavve — редизайн в двух темах: «Классический iOS» и «iPod Classic»

Статус: **в работе**. Фаза 0 (удаление веба) выполнена.

---

## 1. Замысел

Пользователь не должен чувствовать, что у него «приложение на телефоне». Он должен
чувствовать, что у него **плеер**. Два уровня этого:

- **«Классический iOS»** — плотный тёмный интерфейс, крупные ряды обложек,
  голубой iOS-акцент, Cover Flow в плеере, нижняя навигация.
- **«iPod Classic»** — графит с текстурой, меню с классическими иконками,
  бегущая строка заголовка, scroll wheel, экран загрузки с полосой прогресса,
  проценты свободного места, монохромный интерфейс.

Темы **не переключают цветовую схему** — это два разных продукта внутри одного
приложения. Переключение — в настройках, и на первом запуске.

## 3. Архитектура: скин вместо темы

Текущий `ThemeSettingsController` меняет цвет и радиус. Новая модель — **скин**,
который решает, как выглядит и ведёт себя экран.

```
lib/design/
  skin.dart              — абстракции Skin, SkinScope (InheritedWidget), AppSkinScope.of(context)
  ios/
    ios_skin.dart        — IosSkin (реализация Skin)
    ios_tokens.dart      — цвета/типографика/радиусы/отступы iOS-темы
    ios_icons.dart       — набор иконок
    ios_widgets.dart     — IOSButton, IosListRow, IosSectionHeader, IosCard, IosChip, ...
    ios_shell.dart       — навигация, нижняя панель, переходы
    screens/…            — IOSHome, IOSPlayer, IOSLibrary, IOSSearch, IOSStats, IOSSettings
  ipod/
    ipod_skin.dart
    ipod_tokens.dart
    ipod_icons.dart
    ipod_widgets.dart    — IpodMenuButton, IpodListItem, MarqueeTitle, ScrollWheel, …
    ipod_shell.dart
    boot_screen.dart     — только здесь: экран загрузки
    screens/…
  assets/
    graphite_texture.png — текстура графита
```

### Интерфейс `Skin`

Скин отвечает на два уровня:

1. **Навигация** — `SkinShell` (каркас: где навигация, как выглядит, какие переходы).
2. **Экраны** — по интерфейсу на экран: `skin.buildHome(ctx)`, `skin.buildPlayer(ctx)` и т.д.
   Это позволяет темам иметь **полностью разную вёрстку**, а не одну вёрстку
   с двумя наборами констант.

Данные и состояние экранов **не дублируются**. Сейчас `home_screen.dart`,
`library_screen.dart` и др. смешивают провайдеры и вёрстку. Первым шагом логика
выносится в `*_controller.dart` (без UI), а файлы экранов превращаются в тонкие
обёртки `switch (skin) { … }`.

### Переключение темы

`ThemeSettingsController` → `SkinController` (Riverpod). Хранит `SkinId.ios | SkinId.ipod`.
`MaterialApp.router` выбирает роутер темы:

- `core/routing/ios_router.dart`
- `core/routing/ipod_router.dart`

Оба знают общие пути (`/`, `/player`, `/search`, `/library`, `/stats`, `/settings`, …),
но ведут на разные виджеты.

## 4. Дизайн-система

### Токены

Обе темы реализуют один интерфейс токенов:

- `colors` — фон, поверхности, разделители, текст (3 уровня), акцент, семантика
- `typography` — display / title / headline / body / caption / micro, с трекингом
- `radii` — sm / md / lg / pill
- `spacing` — шкала 2/4/8/12/16/24
- `motion` — кривые и длительности (iOS: easeInOut для переходов, 350мс push)
- `texture` — null для iOS, текстура графита для iPod

`ThemeData` продолжает собираться из них (M3), чтобы не ломать существующие
виджеты (`Slider`, `TextField`, `PopupMenuButton`).

### Общие компоненты

Собираются из скина, но API один:

- `TrackRow` — строка трека (iOS: скруглённая с бейджем; iPod: монохромная строка)
- `SectionHeader`, `EmptyState`, `LoadingState`, `ErrorState`
- `MiniPlayer` (форма разная)
- `CoverFlow` (только iOS)
- `MarqueeTitle` (только iPod)
- `ScrollWheel` (только iPod)

### Иконки

Собственный нейтральный API `AppIcons` (`play`, `next`, `search`, `library`, …),
за которым стоят две реализации: iOS-линии и iPod-глифы. Material `Icons.*` из
нового UI убирается полностью (в существующих файлах — 163 использования; они
заменяются по мере переделки экранов).

## 5. Ключевые элементы iOS-темы

- **Палитра**: фон `#1C1C1E`, поверхности `#2C2C2E`/`#3A3A3C`, разделитель
  `#38383A`, текст `#FFFFFF`/`#EBEBF5 60%`/`#EBEBF5 30%`, акцент `#0A84FF`.
- **Плотность**: строка трека 36px, обложка 44px, отступы 16/8.
- **Навигация**: нижняя панель из 4 вкладок, иконка 24px, активная — акцент,
  подпись 10px. Пункт «Настройки» — шестерёнка в правой части шапки.
- **Главная**: приветствие, «Моя волна» крупной карточкой с градиентом от обложки,
  чипы жанров/характера/настроения в один ряд, горизонтальные ленты обложек 160px,
  сетка источников 2 колонки.
- **Плеер**: обложка ~72% ширины, под ней название/артист/альбом, прогресс-бар,
  ряд: shuffle / prev / play(круглая) / next / repeat, нижний ряд инструментов.
  **Cover Flow**: свайп влево-вправо листает очередь, центральный трек — текущий,
  соседние повёрнуты в 3D (перспектива), при смене трека анимация высотается по Y.
- **Переходы**: push — справа, pop — влево, 350мс `easeOutCubic`. Модалки — снизу.
- **Караоке**: остаётся как есть, перекрашивается только под iOS-палитру.

## 6. Ключевые элементы iPod-темы

- **Фон**: графит `#0E0E10` + текстура (шероховатость/штриховка), панели `#1A1A1C`
  с 1px светлой рамкой — эффект корпуса.
- **Монохром**: только белый/серый. Единственное цветное пятно — логотип на экране
  загрузки (жёлтый/фиолетовый из `Wordmark`).
- **Типографика**: Inter с плотным трекингом, заголовки прописными с разрядкой.
- **Меню**: сетка классических иконок iPod (Playlists / Artists / Albums / Songs /
  Videos / Genres) с виньетками и подписями под ними.
- **Бегущая строка**: заголовок экрана едет влево-вправо, если не влезает.
- **Scroll wheel**: круглый контрол; крутится пальцем по вертикали, выбирает
  элемент, центр — выбор. Используется на экране очереди/плейлиста.
- **Проценты места**: в шапке — «Music 2,4 ГБ · Free 3,2 ГБ» шрифтом LCD.
- **Плеер**: обложка сверху, ниже название/артист/альбом мелким шрифтом, затем
  тот же ряд управления, что в iOS (iOS-круглая кнопка — ради единого управления
  и узнаваемости), ниже прогрес с временами. Различие с iOS — в обрамлении:
  зерно и блик графита, монохромная палитра, LCD-подписи времён. Таймер
  сна/эквалайзер/радио — через иконку меню справа.
- **Главная**: меню иконок iPod — сетка 3×3 плиток с виньетками (плейлисты,
  артисты, альбомы, треки, жанры, избранное, загрузки, настройки, статистика).
  Это то, чем iPod действительно жил: не лента обложек, а меню разделов.
- **Экран загрузки**: логотип vvavve, полоса прогресса, подпись «Loading…»,
  показывается при старте приложения в iPod-теме (в iOS-теме — обычный splash).

## 7. Экраны вне двух тем

- **Караоке/текст песни** — общий, перекрашивается по токенам скина.
- **Экран артиста / альбома / чартов / списка треков / очереди** — общий скелет,
  вид через скин-виджеты.
- **Статистика** — общая логика, две вёрстки (iOS: сетка метрик; iPod: таблица).

## 9. План работ по фазам

Каждая фаза — отдельные коммиты. Субагенты работают параллельно только внутри
фазы 3 — там файлы не пересекаются.

### Фаза 0 — удаление web (1 агент, отдельный коммит)
Выпилить web-код по §8, добиться зелёных `flutter analyze` и `flutter test`.
Проверить `android/app/build.gradle.kts`, `AndroidManifest`, firebase-конфиг.

### Фаза 1 — фундамент (1 агент)
- `lib/design/` — интерфейсы скина, оба токена-набора, текстура, оба набора иконок.
- `SkinController` + миграция/сброс старых ключей `ap_*`.
- Два роутера, переключение в `app.dart`.
- `SkinScope` + `switch (skin)`-обёртки на текущих экранах (заглушки скин-экранов
  повторяют текущий вид — чтобы не сломать сборку между фазами).
- Экран загрузки iPod-темы, первый экран выбора темы.

**Гейт:** analyze/test зелёные, приложение работает, тема переключается.

### Фаза 2 — выделение логики (2 агента, параллельно)
- Агент A: `home`, `search`, `charts` → контроллеры без UI.
- Агент B: `library`, `stats`, `settings` → контроллеры без UI.

Провайдеры и бизнес-логика не меняются, только выносятся из `build()`.

### Фаза 3 — экраны (5 агентов, параллельно)
- **Агент S — Shell**: нижняя панель iOS, меню iPod, шапки, переходы, мини-плеер
  в двух видах, бегущая строка, scroll wheel, проценты места.

**Гейт по каждому агенту:** `flutter analyze` без ошибок, существующие тесты зелёные,

## 10. Риски

| Риск | Что делаем |
|---|---|
| Две темы разъедутся по качеству | Кириллический чек-лист для каждого агента в Фазе 3 |
| Cover Flow тормозит на слабых устройствах | `RepaintBoundary`, ограниченное число соседей (5), отключение в режиме «минимум» анимаций |
| Scroll wheel конфликтует со скроллом списка | Wheel = отдельный слой со своим `GestureDetector`, список под ним; при `AnimLevel.min` заменяется на обычный список |
| Текстура графита ест батарею | Текстура — статичный PNG, не шейдер; только в iPod-теме |
| Потеря пользовательских настроек | Сброс согласован осознанно |
| Регрессия в логике при выделении контроллеров | Фаза 2 ничего не меняет визуально; гейт — тесты |
| `palette_generator` discontinued | Не расширяем использование; в iOS-теме акцент фиксирован |

## 11. Критерий готовности

1. Обе темы включаются в настройках, переключение мгновенное, переживает перезапуск.
2. Ни одного `Icons.*` из Material в новом UI (проверяется грепом).
3. Ни одного `BorderRadius.circular` и `fontSize:` вне дизайн-системы.
4. Ни одного хардкода `Color(0x…)` в UI-слоях.
5. Analyze/test зелёные, golden-тесты в репозитории.
6. APK собирается, ручной прогон на устройстве.
7. Дисклеймер — только в «О приложении».
8. `kIsWeb` не встречается в коде.
