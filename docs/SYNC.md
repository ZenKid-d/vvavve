# Синхронизация

vvavve — приложение Android-only. Веб-сборки больше нет: ни `web/`, ни
`main_web.dart`, ни прокси в `server/`, ни `firebase.json`. Синхронизация между
устройствами при этом работает как раньше — она ходит напрямую в Firestore.

## Firebase

Проект `count0-8424b`. Конфигурацию генерирует `flutterfire configure`
(`lib/firebase_options.dart` + `android/app/google-services.json`) — оба файла
коммитятся: там публичные идентификаторы, а настоящая граница безопасности —
правила Firestore.

Вход через Google сделан фасадом `core/auth/auth_service.dart`: на Android это
системный диалог `google_sign_in`, чьи токены обмениваются на сессию Firebase.
Экземпляр `GoogleSignIn` один на приложение
(`core/auth/google_sign_in_shared.dart`): раньше импорт лайков YouTube держал
собственный, а два экземпляра делят один аккаунт и незаметно ломают друг другу
`signOut`. Скоуп `youtube.readonly` при обычном входе не запрашивается — он
чувствительный, и его наличие потребовало бы верификации приложения у Google.

**Правила Firestore лежат в `firestore.rules` и должны быть опубликованы**,
иначе база останется с дефолтными (заблокированными или, хуже, открытыми):

```bash
firebase deploy --only firestore:rules
```

Без входа приложение работает полностью — синхронизация только добавляется.

## Что ездит между устройствами

Лайки, лайки/дизлайки альбомов, дизлайки треков, плейлисты, подписки и чёрный
список артистов, статистика прослушиваний, а также очередь с позицией. **Не**
синхронизируются токены источников, загрузки и оформление — они привязаны к
устройству по смыслу.

## Механика

Одна на всё: приём чужих правок по курсору серверного времени, слияние локально,
отправка своих — тех, что новее водяного знака. Указатели хранятся отдельно по
аккаунту. Ключевые решения и почему именно так:

- **Надгробия.** Удаление — это запись «удалено» с новой меткой. Без них снятый
  лайк неотличим от никогда не поставленного, и он вернётся с другого
  устройства.
- **Счётчики по устройствам.** Каждое пишет только свой счётчик, показывается
  сумма. Одно общее число росло бы при каждом обмене: 5 + 3 → 8 → 13 → …
- **Монотонные метки** (`SyncClock`): при откате часов запись оказалась бы
  «старее» уже отправленного и навсегда осталась невидимой для отправщика.
- **Сессия — по согласию.** Чужая очередь не подменяет свою молча: приходит
  предложение «продолжить такой-то трек с телефона». Очередь режется окном в
  100 треков вокруг текущего — в режиме радио она бесконечна.
- **Вход в другой аккаунт** на устройстве, где уже была синхронизация, включает
  только приём: библиотека первого хозяина не должна уехать в чужой аккаунт.

Транспорт спрятан за интерфейсом `SyncTransport`. Если Firestore в России
станет недоступен, замена на REST через собственный прокси стоит одного класса.

## Обход блокировок

Живёт в `lib/core/net/`. DoH-резолвер и HTTP-прокси подставляются в `HttpClient`
dio и в http-клиент `youtube_explode` — оба читаются на старте приложения,
поэтому смена настройки требует перезапуска. Настройки — в разделе «Настройки →
Сеть».

Если понадобится серверный прокси для всего трафика, точка врезки та же, что была
у веб-версии: перехватчик dio плюс подмена ссылки потока у источника. Оба места
в коде помечены комментариями.
